# Core 活动通知与断线诊断

## 根因与边界

2026-09-20，Core 0.8.44 在真实模型运行中发送 `turn/activity`，实测字段为 `threadId`、`turnId`、`source: "provider_stream"`。旧 Host 白名单缺少该通知，抛出 `CodeM App Server emitted unknown notification turn/activity`，随后 ChatController 进入 disconnected 并主动关闭 Core。纯文本请求即可复现，不依赖 `ask_user` 或 `final_answer`。

本次只补齐这个已观测到的协议边界，以及连接失败的分类反馈。不改变强制收尾、模型配置、认证策略或工具权限。其他未知通知仍报协议错误，不将任意未知协议静默忽略。

## 完整行为

- 首次连接只启动现有 Core 连接；发送前后沿用既有认证与 RPC 调用链。此次修改不新增认证、目录查询、RPC 或子进程。
- `turn/activity` 由 App Server Host 校验并投影成 `turn-activity`，只接收所属连接、当前 thread 和当前 turn 的事件，要求明确非空的 turnId/source。
- 它是运行活动通知，不是消息、轮次开始或终态。首次及重复通知都不创建卡片、不重置计时、不改变等待提问/停止状态。仍由 `turn/completed` 结束实时轮次。
- 已完成、已退订、切换上下文后的通知不能恢复旧轮次。它不进入 JSONL 历史投影，不新增缓存或持久化状态；重载沿用正常会话恢复。
- 连接异常分类为协议错误、认证失效、进程退出；界面和 CodeM 日志显示同一脱敏分类。进程退出保留操作系统提供的退出码/信号；不把 Core 原始错误消息、协议帧、工作区路径或凭据转发给 Webview 或输出日志。已有消息保留，计时停止，旧连接由 retire 回收；用户可重新连接。

## 验证入口

- `pnpm check`：通知归属、重复/过期事件、非法字段、现有未知通知拒绝、计时终态、故障分类脱敏与重连。
- `pnpm --filter codem test:live --headless`：显式真实模型验收，复用独立临时工作区中的一个 Core，不新开 VS Code；验证普通回复、真实问答面板提交、取消提问、停止和下一轮。默认检查不调用模型。
- `pnpm build:vscode`：加载新构建后，已有开发宿主需重载以使用更新后的 Host。

## 2026-09-20 验收结果

- 单元/集成：隔离工作树 `pnpm check` 通过，包含通知协议、异常提示、重连与终态回归。
- 当前共享工作区：构建与本次 10 项定向回归通过。全量检查在并行改动的 `thread/read.name` 新字段与旧断言不一致处失败，测试进程未自行退出后被清理；该无关变更未纳入本次提交。计时测试只断言消息、计时和轮次状态不被活动通知改变，允许独立的活动状态展示。
- 模拟界面：Playwright 在深浅主题均验证分类提示可见、点击连接发送 `connect`、输入恢复，4 条已有消息保持 4 条。使用模拟传输，不代表真实 Core 重连或 VS Code 验收。
- 真实 Core 0.8.44：原实现真实纯文本请求因未知 `turn/activity` 断线；修复后普通回复、问答提交、取消提问均完成，同一连接保持可用。一次观测连接 1367 ms，普通回复 2668 ms，问答 4960 ms，取消提问 4439 ms。没有新增生产 RPC 或子进程。
- 扩展真实测试仍失败：立即停止后马上发送下一条，上一条计数回答出现在新轮次，而新请求的标记未返回。连续复现，原始协议已经带有新 turnId，Host 并未改写该标识。停止后的 `turn/completed(interrupted)` 也已到达。保留 `after-stop` 严格断言，未通过延时、重试或忽略失败掩盖它；不能将完整 `test:live --headless` 报为通过。
- 真实 VS Code：现有开发宿主可见于进程与日志，但当前原生 UI 自动化只能定位到另一主窗口，未完成修复后的实际点击验收。未另开开发宿主。

## 后续独立变更：Core 早停后的轮次隔离

优先级高：已连续观察到上一条输出被标为下一条 turnId，可能污染对话。边界是 Core 的停止完成与新轮次调度，不能由客户端猜测文本内容或等待固定时长修补。交付结果应是停止完成后，新轮次只收到自己的输出；准出标准为上述 `test:live --headless` 在同一连接的五轮流程全部通过，并覆盖停止发生在 provider 启动前和流式输出期间。此次未修改该独立问题。
