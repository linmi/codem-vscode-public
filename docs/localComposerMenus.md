# 输入栏菜单本地化

当前问题：模式、权限、模型、空间与附件入口复用了连接/设置事务，单纯查看选项就触发认证、Core 启动或模式读取。目标：Webview 持有菜单开关与预置展示，Host 只接收实际选择，拥有校验、持久化、确认与执行。

- 固定项：Agent/Plan、三种权限、四档强度、文件/图片与文件夹类型随构建提供。初次挂载不等待 Host；打开、重复打开和取消不发消息、不启动子进程、不发 RPC。
- 未连接设置：Host 只保存用户改过的字段。沿用 workspaceState 的 `codem.pendingEffort`，模式和权限各增加独立偏好键；无旧数据格式迁移。下一次连接覆盖目标空间相应字段，保存成功后清理待应用值；其他空间使用自己的设置。
- 完全访问：Host 持有确认流程，取消不改值；确认本身不连接 Core。在线应用复用带模式 revision 校验的设置事务。
- 动态目录：连接成功后一次性随快照投影模型/空间的安全展示字段与不透明选项句柄，菜单本地展开；离线不伪造列表、不后台拉取，明确提示连接或发送后可用。默认打开聊天时随自动连接加载，后续显式刷新才重新加载；选择时 Host 验证句柄仍属于当前连接，空间切换仍验证账户与权限。断开清空目录，避免跨账户复用。
- 附件：类型菜单本地展开；实际选择类型才打开 VS Code 文件对话框。选文件无需 Core，Host 校验文件并保留草稿附件到首次发送；取消、连接失败保留已选附件，发送成功清理，新会话/切换空间清理。不持久化文件路径到 Webview。
- 重载：本地设置由 workspaceState 恢复，附件沿用现有内存草稿范围，动态目录随实际连接重建。忙碌、上下文切换时关闭菜单并禁用变更。失败显示可重试原因，禁止静默回退。

准出：菜单打开零消息、离线固定设置和附件零连接、首次发送参数正确、确认取消/保存失败/非法与过期句柄回归；展开后的深浅主题、键盘、窄屏和首屏延迟验证。自动化、模拟界面、真实 Core 与真实 VS Code 操作分层记录。

## 调用链与验证记录（2026-09-20）

- 展开/搜索/取消：React 组件本地状态，零 Host 选择器请求、零认证、零 Core RPC。斜杠入口共用同一菜单，仅草稿编辑走原有同步消息。
- 离线固定项：一次设置消息 → 校验/必要的权限确认 → workspaceState；零连接。离线附件：一次类型消息 → 本地 VS Code 文件对话框 → 文件校验；零连接。首次发送仍只建立一个连接和一个线程，使用预选设置及附件。
- 在线应用：沿用原设置事务的模式读取和 revision 校验；模型/强度确有变化时 resume，权限/工作模式变化时 setModes。空间显式刷新每次读一次目录，刷新失败保留原列表；成功刷新使旧句柄失效。空间切换继续执行现有认证和连接准备，不重复拉取已验证的目录。
- 单元/集成：`pnpm check` 通过，扩展 245 项测试通过；新增离线模式/权限/强度重载与首次发送、完全访问取消与确认期间拒绝发送、目录无请求读取及非法/过期句柄、显式刷新失败和重试、离线附件连接失败保留、图片预览/移除/新会话清理回归。最终 UI 挂载/样式调整再次通过 lint、类型检查和针对性检查。
- 构建：普通扩展与 native-chat 构建通过。
