# 聊天区右下角的任务入口

当前任务列表由聊天区右下角、与“回到最新”按钮平齐的“任务 · 已完成 / 总数”按钮打开。按钮使用本地 shadcn/ui Button，完整清单使用向上展开的 Popover，显示待执行、进行中和已完成状态。没有任务时，HTML 容器默认 hidden，首屏不依赖 Host 返回后再补隐藏。入口悬浮于聊天区，不单独占用输入区的一行；详情向上展开并右对齐。任务入口显示、隐藏和展开不会改变输入框布局，也不会请求 Host / Core；支持重复点击、键盘开启、Escape 关闭及焦点返回。

## 状态与生命周期

- 实时来源是既有 `turn/plan/updated` 的完整列表，经 Host 校验当前 thread/turn 后写入 `capabilities.plan`；输入参数和工具成功回执都不推导任务完成情况。失败、取消、终态和下一轮发送不会清空任务，只有 Core 新列表替换它。
- 历史来源是 schema 13 reducer 已经产生的 `todoSnapshot`。`SessionHistoryPage.todoSnapshot` 是必填且可为 null 的内部字段，在原有单次历史读取中返回整份会话的最新任务状态，不新增扫描、RPC 或子进程，也不受最近 30 轮分页限制。
- 恢复或重新加载会话时，Host 将历史任务内容和状态投影为 `capabilities.plan`；加载更早消息不覆盖当前任务列表，读取失败保留此前状态。
- 新建、清空、关闭会话或连接退役时清理计划；会话恢复后从对应历史重新取得。切换上下文或加载历史时关闭浮层，所有任务完成后按钮仍保留；Core 返回空列表时隐藏入口。
- Host 拥有任务数据，Popover 仅拥有展开和焦点状态，不新增持久化或缓存。已有连接初始化、认证、历史读取及取消机制保持原职责。

## 展示迁移

旧的 `webview/transcript/taskProgress.tsx/.css` 每次调用卡片及其专用消息 DTO 已删除；调用记录恢复通用工具折叠行，白名单输入字段明确标为“期望状态 / 请求操作”，只用于查看那次调用。运行详情中的重复任务列表也已移至新的统一入口。`projectTaskDetails` 保留对 Core 0.8.44 批量、单项、替换、依赖和删除参数的验证，不猜测未知输入。没有兼容入口或旧路径转发。
