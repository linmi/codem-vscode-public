# App Server 能力接入

基线：本机已安装 Core 0.8.44、CLI 0.1.208，`initialize` 实测能力位及当前 Host 类型。
按用户要求由 0.8.37 升至 0.8.44；不启用其明确未支持的 configWrite、HTTP MCP、标准 skill-path 输入。

## 操作与生命周期

- 首次打开能力面板不发 RPC；用户展开目录后显式加载。目录属于当前连接，线程快照属于当前订阅；刷新重新校验认证，不复用失效认证。重复点击由 Host 锁定。
- 实时计划、用量、差异汇总、工具保护和 Hook 结果是内存显示投影。新轮次清理轮次级状态；切换会话/空间清理全部投影。持久消息仍只读 Core JSONL。
- 运行中补充走 turn/steer，仅发送纯文本，绑定 expectedTurnId；回执成功才清除提交内容，失败不重发。旁路提问在主轮次空闲时启动，独立流式区域，取消回执不替代完成事件；断线标记未完成。
- 会话操作只接受当前工作区列表或当前订阅的 ID，执行前 readThread 核验 cwd。改名/分叉/归档/解除归档/删除均单次请求；删除、清空先展示明确作用对象和确认按钮。操作结果不明时保留提示并刷新，不自动重试写入。
- 压缩/回退走 Core 控制轮次，复用现有审批和回退选项，turn/completed 是终态。完成后刷新 JSONL 投影，失败保留原记录。
- 技能选择只允许 Core skills/list 返回的名称，使用原生结构化 skill input；目录变化使旧选择失效。附件与技能输入的组合遵守实测协议，不拼接伪造 slash 命令。
- Shell 由用户明确提交命令，通过 Core thread/shellCommand 执行。额外目录由原生文件夹对话框取得并 realpath 校验，经 thread/resume 应用；只在当前连接内保存，重载必须重新选择。
- 诊断只投影白名单结构：不把原始配置对象、路径、Hook 命令、插件元数据或原始 item 发送给 Webview。配置显示键名与值类型，Hooks 显示事件与处理器数量；不声称具备编辑能力。
- Webview 重建从 Host 快照恢复，表单草稿由 Webview state 保存；会话上下文变化清理目标相关表单。取消表单不发 RPC，迟到回复不能覆盖新上下文。

## 验证门槛

每批运行相关单元/集成测试、类型与 lint 检查；模拟界面验证展开、键盘、失败/取消、窄栏、深浅主题。真实 Core 使用临时工作区核对契约，不操作用户已有会话。真实 VS Code 层复用已有开发宿主或现有 smoke 工具。各层完成情况在交付中分别报告。
