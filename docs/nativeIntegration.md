# VS Code 原生能力接入

## 交互与状态设计（实施前）

- 编辑器解释与选区加入上下文：捕获当前未保存文本、相对路径和行号，追加聊天草稿并聚焦。修复/改进生成局部修改建议，经过原生 CodeLens、双栏 Diff 逐块接受/拒绝后才写入文档，支持撤销；完整生命周期见 [编辑器修改审阅](editorReview.md)。无选区拒绝，Code Action 可取诊断范围；不同工作区不自动切换当前会话。
- 侧栏和编辑器标签页承载同一聊天控制器；同时只有一个可交互聊天表面。重复打开复用标签页；关闭标签页返回侧栏。Host 保存本窗口草稿，Webview state 用于重载恢复，审批迁移保留请求身份。窗口重载后连接和历史规则沿用现状。
- 终端选区由用户显式命令读取；最近命令输出通过 Shell Integration 捕获，每终端仅保留最近一次命令的有界输出，终端关闭或扩展退出时清理，不落盘。缺少可读数据明确提示。解释/修复先进入可编辑草稿，不执行终端命令。
- 生成终端命令（`codem.generateTerminalCommand`，命令面板与终端右键 CodeM 子菜单，对应旧版同名命令；旧版的 `Ctrl/Cmd+Shift+G` 与源代码管理视图冲突，不再绑定）：输入框收集描述 → 复用当前连接的旁问生成一次（与提交说明共用生成槽位，45 秒超时，可在进度通知取消）→ 模态预览 → 插入或复制。只接受单行命令，插入用 `sendText(line, false)`，不按回车，由用户确认后执行。目标固定为发起时的活动终端；预览期间该终端关闭则报错不插入，不改投其他终端；发起时没有终端才新建 CodeM 终端。提示词带平台、Shell 名称和相对当前目录，描述视为数据。并发调用只提示，不重复生成；空描述不调用模型。
- 行内补全支持手动触发和默认开启的停输入 250ms 自动触发，复用当前连接的旁问；只在空闲且工作区匹配时执行。取消、文档修改、光标移动或切换编辑器使结果失效。结果以原生 ghost text 显示，由用户接受；不直接改文件。
- 提交说明基于用户选择仓库的暂存区差异；无暂存变更提示先暂存。只填 SCM 输入框，不提交。取消、输入框被编辑、仓库变更使迟到结果失效，不覆盖用户输入。
- 双栏 Diff 只有在可可靠重建原文和新文时使用；部分/二进制/缺失差异保留显式补丁说明，不伪造完整文件。内容只读、生命周期归预览文档。
- 防休眠（`codem.toggleKeepAwake`，对应旧版 `codem.toggleCaffeination`）：命令开关一个系统抑制进程，macOS `caffeinate -i`、Linux `systemd-inhibit --what=idle:sleep`、Windows `SetThreadExecutionState`；只阻止空闲休眠，不阻止熄屏或合盖。状态只在内存，重载或停用扩展即关闭；抑制进程绑定扩展宿主 PID，宿主崩溃时自行退出。状态栏项仅在开启中/已开启时出现，点击关闭。进程启动失败或自行退出时回到关闭并提示原因（如 Linux 无 systemd 会话总线）。远程工作区中作用于运行扩展与 Core 的远程主机。不调用 Core、不发 RPC。
- 设置只新增已实现的平台行为（自动连接、发送键、补全开关）；模型、权限仍由既有空间隔离偏好和 Core 管理，不创建第二事实来源。

## 聊天工具栏

- 侧栏的新建和历史入口归 VS Code 原生标题栏；连接、登录、日志、设置和展示位置操作在原生 `…` 菜单。Webview 标题栏只保留会话标题、连接状态和文件与工具。
- 编辑器标签页没有侧栏标题栏，Webview 保留新建、历史和日志入口。展示位置由 Host 在挂载时明确传入，不持久化另一份偏好；重复打开、重载或移回侧栏均按实际载体渲染。
- 两种位置仍共用历史面板、控制器、错误提示和草稿。关闭历史面板时，标签页返回历史按钮，侧栏返回输入框；历史加载、失败重试和会话切换规则不变。此调整不增加 RPC 或子进程。

## 调用预算

草稿、切换聊天位置、菜单和设置操作不调用模型、不创建 Core。生成操作复用一次连接；首次无线程时 thread/start 一次；每次旁问授权一次、start 一次，取消至多 cancel 一次，终态以事件为准。禁止并发生成和主轮次；不缓存认证。Git 差异读取前后各一次以确认结果仍适用，不执行 Git 写入。生成耗时记日志，不记录请求文本。

## 外部依据

基线 VS Code ^1.105.1、@types/vscode 1.105.0。使用对应版本的 [稳定 API 定义](https://github.com/microsoft/vscode/blob/1.105.1/src/vscode-dts/vscode.d.ts) 和 [内置 Git API](https://github.com/microsoft/vscode/blob/1.105.1/extensions/git/src/api/git.d.ts)。不引入 proposed API。

## 实现补充

- 补全设置包括总开关 `codem.completion.enabled` 和自动触发开关 `codem.completion.autoTrigger`；关闭自动触发不影响手动命令。没有复制历史补全连接或旧工作区框架。
- 生成请求最多等待 45 秒，超时发出取消；再过 5 秒仍缺少终态则关闭当前连接并明确要求重连，迟到结果不可应用。没有模型结果缓存或自动重试。
- 选区追加由当前 Webview 基于最新输入执行并回执，防止 Host 旧草稿覆盖正在输入的内容；切换聊天表面可重放未确认追加。发送回执沿用草稿修订检查，移动后仍不清除新编辑。
- 原生 Diff 以完整补丁与当前文件的行内容重建，不承诺历史文件字节快照。行尾格式和末尾换行不在 Core hunks 契约中，因此双栏标题注明重建；当前文件无法读取或不匹配时展示明确原因和原补丁。
- 模型和权限偏好继续保持原有空间隔离。新增设置均有真实调用方，未增加历史遗留配置或兼容别名。

## 原生操作补验（2026-09-21）

在同一个现有开发宿主（VS Code 1.138.0；扩展最低 API 基线仍为 1.105.1）完成以下真实操作，未另开宿主或浏览器：

| 入口 | 操作与结果 |
| --- | --- |
| 编辑器修改审阅 | 真实模型生成两块；原文件 CodeLens 和原生 Diff 工具栏均完成预览、接受一块、拒绝另一块；已接受内容可撤销，拒绝内容不写入。详见 [审阅记录](editorReview.md)。 |
| 行内补全 | `Cmd+Alt+\` 在函数末尾触发灰字 `n % 2 === 0`；Tab 接受后核实文件内容；再次生成的分号建议按 Escape 取消，文件不含该分号。模型请求日志记录一次生成调用，接受样例约 1871ms，取消样例约 2169ms；自动请求也实际触发。忙碌时手动操作明确提示等待。 |
| 终端右键 | 新建专用终端运行 `printf` 输出 `CODEM_TERMINAL_ACCEPTANCE`；右键 CodeM → 最近终端输出加入上下文，草稿包含命令及输出；选择该标记后通过“复制终端选区并加入上下文”，草稿只含所选标记。两次均未发送模型消息，验收后清空草稿并关闭该终端。 |
| SCM 生成 | 独立无远程测试仓库只暂存 README 范围说明；从 SCM 原生按钮生成，实际回填“补充原生验收 fixture 的 README 验证范围说明”。Git 上下文约 25ms、生成 4298ms、全程 4336ms；未执行提交，生成输入随后清空。 |

SCM 首次验收发现真实 Git API 每次返回新的仓库包装对象，旧 `repositories.includes(repo)` 恒不匹配，导致成功生成后误报关闭。改为按 root URI 核实，并监听关闭事件取消旧请求；测试现在返回新包装对象，覆盖正常回填、仓库消失、关闭后同 URI 重开，以及输入/暂存/HEAD/会话变化后不覆盖。官方依据见 [Git API 仓库包装实现](https://github.com/microsoft/vscode/blob/1.105.1/extensions/git/src/api/api1.ts#L330-L336)。修复后在同一宿主重新执行 SCM 成功。

验证层次：默认 fixture 单元/集成、lint、类型检查、正式构建通过；真实 Core 修改建议及真实宿主补全/SCM请求通过。没有把单元测试或模拟页面当作原生操作验收；本轮不修改 Webview，未另做模拟界面验收。本轮证明这些入口的操作闭环，不代表复杂代码补全质量、延迟、所有语言/系统及所有取消边界已经穷尽验收；失败和竞态边界由对应回归覆盖。

资源：清理本轮新建的 toolbar.ts、acceptance.ts 和专用终端。原先创建的 `.artifacts/native-acceptance-97glz6vf` 已被用户继续用于手动试用，保留其中 completion.ts、review.ts、README 及独立 Git 仓库，避免删除用户后续试用内容；未改用户主仓库的暂存内容。现有窗口交还用户。
