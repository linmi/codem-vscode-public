# VS Code 原生能力接入

## 交互与状态设计（实施前）

- 编辑器解释/修复/改进、选区加入上下文：捕获当前未保存文本、相对路径和行号，追加聊天草稿并聚焦。用户发送前可编辑或取消；无选区拒绝，Code Action 可取诊断范围。迟到操作不自动发送，原草稿保留。不同工作区不自动切换当前会话。
- 侧栏和编辑器标签页承载同一聊天控制器；同时只有一个可交互聊天表面。重复打开复用标签页；关闭标签页返回侧栏。Host 保存本窗口草稿，Webview state 用于重载恢复，审批迁移保留请求身份。窗口重载后连接和历史规则沿用现状。
- 终端选区由用户显式命令读取；最近命令输出通过 Shell Integration 捕获，每终端仅保留最近一次命令的有界输出，终端关闭或扩展退出时清理，不落盘。缺少可读数据明确提示。解释/修复先进入可编辑草稿，不执行终端命令。
- 行内补全支持手动触发和默认开启的停输入 600ms 自动触发，复用当前连接的旁问；只在空闲且工作区匹配时执行。取消、文档修改、光标移动或切换编辑器使结果失效。结果以原生 ghost text 显示，由用户接受；不直接改文件。
- 提交说明基于用户选择仓库的暂存区差异；无暂存变更提示先暂存。只填 SCM 输入框，不提交。取消、输入框被编辑、仓库变更使迟到结果失效，不覆盖用户输入。
- 双栏 Diff 只有在可可靠重建原文和新文时使用；部分/二进制/缺失差异保留显式补丁说明，不伪造完整文件。内容只读、生命周期归预览文档。
- 设置只新增已实现的平台行为（自动连接、发送键、补全开关）；模型、权限仍由既有空间隔离偏好和 Core 管理，不创建第二事实来源。

## 聊天工具栏

- 侧栏的新建和历史入口归 VS Code 原生标题栏；连接、登录、日志、设置和展示位置操作在原生 `…` 菜单。Webview 标题栏只保留会话标题、连接状态和文件与工具。
- 编辑器标签页没有侧栏标题栏，Webview 保留新建、历史和日志入口。展示位置由 Host 在挂载时明确传入，不持久化另一份偏好；重复打开、重载或移回侧栏均按实际载体渲染。
- 两种位置仍共用历史面板、控制器、错误提示和草稿。关闭历史面板时，标签页返回历史按钮，侧栏返回输入框；历史加载、失败重试和会话切换规则不变。此调整不增加 RPC 或子进程。

## 调用预算

草稿、切换聊天位置、菜单和设置操作不调用模型、不创建 Core。生成操作复用一次连接；首次无线程时 thread/start 一次；每次旁问授权一次、start 一次，取消至多 cancel 一次，终态以事件为准。禁止并发生成和主轮次；不缓存认证。Git 差异读取前后各一次以确认结果仍适用，不执行 Git 写入。生成耗时记日志，不记录请求文本。

## 外部依据

基线 VS Code ^1.105.1、@types/vscode 1.105.0。使用对应版本的 [稳定 API 定义](https://github.com/microsoft/vscode/blob/1.105.1/src/vscode-dts/vscode.d.ts) 和 [内置 Git API](https://github.com/microsoft/vscode/blob/1.105.1/extensions/git/src/api/git.d.ts)。不引入 proposed API。

## 实现补充

- 补全设置包括总开关 `codem.completion.enabled` 和自动触发开关 `codem.completion.autoTrigger`；关闭自动触发不影响手动命令。没有复制历史补全连接或旧工作区框架。
- 生成请求最多等待 45 秒，超时发出取消；再过 5 秒仍缺少终态则关闭当前连接并明确要求重连，迟到结果不可应用。没有模型结果缓存或自动重试。
- 选区追加由当前 Webview 基于最新输入执行并回执，防止 Host 旧草稿覆盖正在输入的内容；切换聊天表面可重放未确认追加。发送回执沿用草稿修订检查，移动后仍不清除新编辑。
- 原生 Diff 以完整补丁与当前文件的行内容重建，不承诺历史文件字节快照。行尾格式和末尾换行不在 Core hunks 契约中，因此双栏标题注明重建；当前文件无法读取或不匹配时展示明确原因和原补丁。
- 模型和权限偏好继续保持原有空间隔离。新增设置均有真实调用方，未增加历史遗留配置或兼容别名。
