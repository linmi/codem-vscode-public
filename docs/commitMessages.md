# 提交说明生成

## 目标与边界

原实现只传入暂存 diff 和一句简短要求，既没有仓库风格参考，也未区分主要行为、配套代码与无证据推断。当前生成由 `integrations/commitMessage.ts` 独立拥有输入规则、提示与输出格式校验；`gitActions.ts` 负责仓库读取、取消和安全回填，既有旁问连接仍由 ChatController 拥有。不引入缓存、额外 Agent 轮次、自动重试或自动提交。

依据完整暂存差异概括主要目的；标题具体，简单改动只写标题，复杂改动按目的补充短正文。描述用户行为，避免罗列文件、类名与方法。最近 8 条非合并提交仅提供语言和格式参考，每条最多 160 字符且不传递正文；至少两条且占三分之二时判定明确惯例。中文/英文多数语言及 Conventional Commits 格式由客户端确定后明确传给模型；其他语言或混合历史使用 VS Code 界面语言，不强制 Conventional Commits。不从历史或聊天推断本次变更，不声称新增测试已通过。

## 操作语义

- 首次与重复使用：选择工作区仓库，仍要求已连接且空闲。进度通知允许取消；同一时间只有一个生成操作。每次重新读取暂存区和历史，没有跨操作状态。
- 输入：完整差异最多 24000 字符，空差异或超限明确失败，不截断。无 HEAD 的新仓库跳过历史读取；其他历史读取错误明确失败，输入框保持原状。历史只传标题，不含作者信息。
- 生成：输出 JSON `message`，解析后验证非空、控制字符、长度、标题不超过 100 字符、正文与标题间空行和无 Markdown 围栏。格式错误可重新点击生成，不自动发第二次模型请求。
- 取消与失败：取消历史读取期间的操作不会再调用模型；Git API 本身未提供取消参数，已经启动的本地读取完成后丢弃结果。生成期间复用既有旁问取消。任何失败不覆盖输入框，重试重新读数据。
- 回填：原输入非空时先询问替换。生成后再次读取暂存差异，并验证输入框、HEAD、仓库归属及最终复核期间的聊天上下文；任一变化都拒绝写入。首次生成合法创建的聊天 thread 不会被误判为切换。
- 重载与关闭：扩展销毁取消未完成操作；不持久化生成中的结果。更换仓库/分支、工作区或会话使旧结果失效。

Git API 依据项目最低版本 [VS Code 1.105.1 官方类型](https://github.com/microsoft/vscode/blob/1.105.1/extensions/git/src/api/git.d.ts) 核实 `Repository.log`、`maxEntries`、`maxParents`、`range` 和 `state.HEAD`。一次成功操作：本地暂存 diff 两次（输入/回填核验）、log 一次（新仓库零次）、模型旁问一次；复用连接，必要时首次创建 thread，认证仍按现有旁问调用链校验。日志只记录上下文、生成及总耗时，不输出 diff 或身份。

## 真实运行发现的协议问题

固定 Core 0.8.44 在旁问 started 通知中回显 trim 后的 question；Host 原先保存未经 trim 的请求。Git diff 尾换行会令回显少一个字符，触发内容不匹配并断线。Host 现于 startSideQuestion 边界统一首尾空白，发送与关联同一份文本，保留内部缩进和空行，仍严格拒绝真正不匹配的响应。fixture 同步模拟 Core 行为，覆盖正常完成与错误内容拒绝，而不是在提交说明调用方裁剪来掩盖协议问题。

## 质量验收

`pnpm --filter codem test:live --commit-messages` 显式启用真实 Core，使用一个临时无 GUI 工作区和一个连接，依次发送三次旁问，不操作用户暂存区或提交输入框，不产生 Agent turn。样本保存在 `tests/fixtures/commitMessages/`，来自本仓库的完整文件差异：`3d0ba37` 的头像读取/展示、`ca57ef8` 的多选区管理、`3d0ba37` 的 README 更新。来源均为本项目，不依赖本机 Git 历史存在或历史目录。

自动检查语言/格式惯例、主要对象、无捏造测试通过，以及正文不退化成特定类名/方法清单；还必须人工阅读结果，判断是否准确、简洁、重点合理。这些有限样本不能保证任意仓库的生成质量。

2026-09-20 验收：全量 `pnpm check` 通过，正式扩展构建通过。首次真实生成暴露上述首尾空白断线；修复后真实 Core 连通，后续质量轮次分别发现语言未遵循历史、正文过多罗列方法。现在语言/格式的明确多数规则由客户端确定，并收紧正文要求，最终三份样本均通过自动准出。最近一次连接 2478 ms，三次生成分别 3234 / 4005 / 2068 ms；1 个连接、3 次旁问、0 次 Agent turn。

最终输出标题示例：`Show the signed-in user's avatar image in the account view`；`feat(chat): 支持固定多段代码选区并按 id 批量引用`；`更新 VS Code 扩展文档：头像改为展示真实头像并在图片不可用时回退姓名首字`。人工阅读确认主变化和仓库语言正确，文档场景没有宣称实现新功能；多选区正文仍偶有 id/uri 技术词，风格质量存在模型波动，不能将格式测试视为语义质量保证。
