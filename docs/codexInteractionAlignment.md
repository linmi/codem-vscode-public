# CodeM 与 Codex 桌面交互对照

核对日期：2026-09-19。基线：8047f2a。目标是 CodeM VS Code 客户端的聊天交互，不是复制整个 Codex 桌面产品。

## 证据与边界

- 用户选择 Codex 桌面 App 为参考。CUA 明确禁止访问 com.openai.codex，未完成参考 App 的实机逐项观察，不宣称像素、动画或全部快捷键一致。
- 官方文档现已将旧 Codex App 页面重定向至 ChatGPT 桌面文档；下列依据只采用明确涉及 Codex/桌面的说明，不把 CLI 快捷键套用到插件。
- [项目和会话](https://learn.chatgpt.com/docs/projects)：项目组织、会话新建/恢复、搜索、重命名、置顶、归档。
- [追加指令和排队](https://learn.chatgpt.com/docs/prompting#steering-and-queuing)：Steer 修改当前执行，Queue 留到下次执行；排队项可编辑、重排、发送、删除。
- [权限](https://learn.chatgpt.com/docs/permission-modes)：权限入口在输入区下方；审批和沙箱是两个维度。
- 当前实现依据 apps/vscode/src、webview 和 tests。底层能力依据 packages/app-server/src/host.ts、authentication.ts。CodeM CLI/Core 固定版本不改变。
- 下表的“合理性要求”是本客户端的验收条件，未经官方文档或实机确认的细节不冒充 Codex 原样行为。

## 逐项核对

| 项目 | 当前实现和差异 | 合理性要求 / 验收条件 |
| --- | --- | --- |
| 登录入口 | 仅未登录时打开浏览器；依赖已打开工作区 | 登录、连接、取消和失败状态可区分；不把工作区连接按钮当账号状态 |
| 注册 | 同一 CodeM 授权网页承接，未实测新账号 | 网页完成后能返回插件继续，不另造注册协议 |
| 退出/换账号 | 底层 signOutAppServer 存在，插件缺入口 | 关闭旧账号连接与在途请求，退出后显示真实状态，不自动登出用户做测试 |
| 空间切换 | 当前空间优先；连接后无切换入口 | 显示所选空间，切换后旧请求无权更新新界面 |
| 新会话 | 当前任务闲置时可新建，生成时禁用 | 不误删持久记录；新草稿不能串入旧会话 |
| 历史恢复 | 当前工作区列表、最近 30 轮和分页已接入 | 原 threadId 续聊；读取失败保留当前内容；不覆盖实时输出 |
| 历史组织 | 缺搜索、置顶、重命名和归档操作 | 底层不支持的写入不伪装成成功；持久元数据所有权需明确 |
| 多任务切换 | 只持有一个活动会话；运行中禁止切换 | 与桌面并行任务体验有明显差异；需独立生命周期设计 |
| 会话草稿 | Webview 只保存一个 draft | 按会话隔离；返回会话恢复各自内容；当前未对齐 |
| 发送确认 | 本轮修复：由请求 ID 对应的 Host 回执消费草稿 | 未确认/失败不清空；拒绝重复与过期回执；等待时新编辑不被清除 |
| 发送失败 | 本轮修复：未确认发送移除本地乐观消息，保留草稿 | 不自动重发；连接中断时提示先核查会话，避免重复执行 |
| 回执丢失 | 本轮修复：已收到 turn/started 时仍保持运行 | 不把回执错误伪装成任务终止；以 Core terminal 结束 |
| 键盘输入 | Enter 发送、Shift+Enter 换行、输入法保护 | 中文组合输入不发送；Tab 保持焦点导航，不照搬 CLI 快捷键 |
| 运行中追加 | 底层 steerTurn 存在，UI 尚未接入 | 明确区分追加当前任务与排队；不能自动停止后重发 |
| 排队 | 当前无队列 | 可编辑/移除；停止或失败后不能擅自推进；需独立实现与验证 |
| 停止 | interrupt 回执不终结，等待 turn/completed | 停止中禁止重复点击；停止后继续异常此前实测未解决，不能标为完成 |
| 模型与强度 | Core 目录和内置档位；原生选择器；运行中锁定 | 显示实际生效值，失败回滚；不把 CodeM 档位冒充 Codex 型号能力 |
| 权限 | 输入区下方；完全访问有显式确认 | 保留 CodeM 的 default/auto/yolo 语义，不声称与 Codex 沙箱等价 |
| 计划模式 | 原生选择器；Core mode revision 校验 | 模式变更与执行计划分开；当前长计划在 QuickPick 中难以完整审阅 |
| 权限审批 | 原生 QuickPick，非对话内卡片 | 能阅读完整操作并拒绝；关闭展示不应等同于授权；内联体验未对齐 |
| 问答 | 原生串行 QuickPick/InputBox | 多题和多选有清晰进度、返回/取消、必填校验；当前待改进 |
| 附件 | 文件选择器、剪贴板图片、去重、限制、发送前校验 | 可移除、缩略图与放大；仍缺拖拽。图片粘贴的分层验证见 [交互验收记录](interactionAcceptance.md) |
| 思考/工具过程 | 实时卡片、callId 合并、状态展示、保留折叠选择 | 不把缺失结果推断为成功；当前已具备基础行为 |
| 消息内容 | 文本和代码围栏 | 缺完整 Markdown、代码复制及链接体验，当前未对齐 |
| 文件差异 | 统计与只读补丁文档 | 可看完整/部分差异；没有并排逐行审阅、评论或应用/撤销按钮 |
| 后台任务 | 轮询、日志、终止、清理已接入 | 任务和进程 ID 分开；不因刷新抢焦点 |
| MCP | 原生配置、SecretStorage、按需发现 | 不将工具目录称为健康状态；当前管理入口与任务资源混在一起 |
| 阅读与焦点 | 接近底部时跟随，历史前插保留位置 | 缺回到底部入口；历史开关缺显式焦点恢复；待补齐 |
| 故障恢复 | 通用提示与日志；断线停止更新 | 不靠自动重发掩盖失败；登录失效需要明确重新认证入口 |
| 桌面专有能力 | 浏览器、语音、跨设备、自动化、worktree 不在本插件已确认范围 | 不为外观一致添加无后端按钮，不把它们算成聊天对齐完成 |

## 本轮验证

发送控制器和草稿回执回归覆盖：重复提交、旧回执、失败重试、发送期间编辑（含相同文本）、Core 已开始但 RPC 回执失败、快速结束不复活。默认检查不调用真实模型。pnpm check 通过：157 项测试（VS Code 56、App Server 83、历史 12、协议 6），lint 和类型检查通过。pnpm build:vscode 通过。真实 pnpm --filter codem test:live 在 VS Code Extension Host 内确认提交已接收、2 次流式 delta、Core completed 和界面状态 ready；此次未逐项操作原生 Webview 控件，也未回归此前的停止后续聊异常。最后附件消费逻辑整理后，VS Code 56 项测试和类型检查再次通过。

## 仍需完成的优先顺序

1. 输入和任务生命周期：接入 Steer/Queue、会话草稿隔离，并定位真实停止后续聊异常。边界为当前聊天控制器与输入区；准出为真实 Core 中追加、停止、失败恢复均不丢消息、不串会话、不重复执行。
2. 账号及人工交互：登录状态与退出入口、可完整审阅的审批/计划/问答，再补消息和差异阅读。边界为账号服务和严格 DTO 的交互展示；准出为取消不授权、失效请求不可提交、成功/失败/重登路径可判定。
