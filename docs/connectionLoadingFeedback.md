# 连接状态提示

连接、发送及等待首段回复统一复用 `workingRow` 的「正在思考与处理…」。`transcriptLoading` 仅用于恢复历史记录。此前对话区、连接按钮、模型按钮分别展示加载文字，footer 还重复播报状态。

- 首次打开：默认直接显示欢迎页，隐藏连接操作区和加载反馈，允许输入及发送。发送后直接展示处理状态，连接过程不再另开初始化界面，暂时禁用模型等操作。
- 断线后重连：保留已有消息，同时展示同一个加载反馈；不额外保存 UI 连接状态。
- 成功：加载反馈消失；失败或授权取消返回 disconnected 后，恢复连接、登录入口并展示 Host 提供的 notice，允许再次尝试。
- 历史恢复继续由对话区播报，移除 footer 的重复播报。重载及切换上下文均以最新 ChatSnapshot 为准；不改变连接、取消、RPC 或子进程生命周期。

验证：扩展类型检查、构建、52 项控制器测试、脚本语法及 diff 检查通过。复用 4318 服务和单个临时浏览器标签页，验证浅色 440px 连接中只有一个提示，以及深色断线记录、重试入口和模拟重连成功后清理。`lifecycleViewChecks.mjs` 增加重复提示、带消息重连及连接失败可重试断言；独立浏览器脚本未执行。未调用真实 Core；真实 VS Code 操作本轮未执行，保留现有用户会话。

## 首次操作时连接

默认 `codem.autoConnect=false`，首次普通消息在 Controller 内完成连接后继续同一次发送。Webview 与 Host 都允许未连接时提交普通消息；请求标识和草稿修订继续由现有 ComposerSubmission / ChatSurfaces 管理，成功回执才消费原草稿，新编辑和失败草稿保留。Controller 只持有一个进行中的发送请求，重复提交立即拒绝；连接失败、选择取消、工作区不可信、宿主退出均不继续发送。新会话或连接代次变化会使尚未发送的请求失效，不持久化自动重试队列。

主动选择模型、模式、权限、思考强度、空间、附件或历史同样可以触发连接；选择器取消后保留已建立连接，不创建 thread。后续发送复用该连接。历史和设置异常导致断开后，新的显式发送重新连接并创建新会话，不向状态不明的旧 thread 发送。重载恢复草稿，但默认不建立连接或自动发送。

保留已有公开设置 `autoConnect`，尊重用户显式启用提前连接的选择；只改变默认值和说明，没有临时兼容分支或新缓存。

调用链：首次发送 → connect → 既有认证/空间准备 → 一个 App Server 连接 → 一次模型目录读取 → MCP 与偏好恢复 → thread/start → turn/start。连接完成后不再次初始化或拉取模型目录，后续消息仅走原有发送路径；原有授权校验、Connection runtime / MCP / phase 分段耗时日志不变。打开界面默认零连接，重复提交必须保持一次连接、一次 thread/start 和一次 turn/start。

本次验证：`pnpm check`（含 183 项 VS Code 测试）、扩展构建、脚本语法及 diff 检查通过。控制器与命令测试覆盖首次发送、无效输入不连接、重复发送、连接失败/取消后重试、授权拒绝、退出后迟到连接回收、新会话失效、模型选择及历史按需连接；原草稿回执测试继续覆盖失败和后续编辑保留。模拟界面验证默认无加载、未连接发送可用、拒绝回执保留草稿。独立生命周期浏览器脚本已更新，未执行；未运行真实 Core 模型请求。现有 VS Code 窗口检查为空闲，但尝试重载时用户接管了窗口，未完成真实宿主验收。


## 连续处理反馈

首次提交至连接、发送、等待首段回复共用同一行文字与动画；连接完成但发送回执尚未返回的间隙，由既有 ComposerSubmission.busy 衔接，欢迎页不会闪回。实际回复进度接管后移除占位；失败回执、关闭/重载、切换输入上下文仍按原有请求生命周期清理，不新增持久状态。审批、问答、计划确认和停止继续显示可操作状态，历史恢复单独显示「正在恢复会话记录」。移除 footer 对发送/运行/停止的重复屏幕阅读器播报，统一由 workingRow 的 status 区域播报。

本次为纯显示层调整，连接次数、RPC、认证、取消与发送语义未变。静态检查、扩展类型检查、构建及 6 项处理状态/草稿回执测试通过；生命周期回归脚本同步且语法检查通过，未单独运行。复用现有预览服务和一个临时标签页，检查浅色连接、深色发送和历史恢复场景，连接不再显示初始化骨架，发送保持相同处理提示。未运行真实 Core 或真实 VS Code 操作；临时标签页关闭、视口恢复。

## 提交时立即显示消息

之前消息在 `ensureThread` 完成后才加入列表，因此等待连接期间先显示处理提示，稍后插入用户气泡导致跳动。现在 Controller 在接收有效提交时创建唯一 submissionId 和待发送消息；每个快照在正式消息尚未写入时投影该消息，连接绑定与 thread 创建均不丢失它。正式发送复用相同 ID，Webview 保留同一个 DOM 节点。收到 Host 消息前不抢先隐藏空白欢迎页展示孤立处理提示。

待发送消息只属于当前 Controller 的发送请求，不写入 Core 历史；接受后由正式消息承接，失败/取消后移除预览，原草稿按已有回执协议保留。重试生成新 ID；新会话、迟到连接、退出继续遵守发送请求失效规则。重载 Webview 可以从 Host 快照恢复仍在等待的气泡；退出 Host 不自动重发。不增加连接、目录读取或 RPC。

验证：类型检查、构建、静态检查、186 项扩展测试通过。新测试阻塞连接与 thread/start，逐个检查全部快照中的消息 ID 和数量，并验证失败撤回、重试身份。新增两秒慢连接预览；复用现有服务和单个临时标签页，实测 connecting 时气泡已出现，running 时仍为同一个可访问节点，位置与处理提示一致。`lifecycleViewChecks.mjs` 加入 DOM 节点与坐标连续性断言，语法检查通过，未独立执行。未运行真实 Core 模型或真实 VS Code 发送验收。
