# 连接状态提示

空白会话连接时由欢迎区的 Logo 动效体现初始化，欢迎语仅在 `ready` 后显示；已有消息时，连接、发送及等待首段回复统一复用 `workingRow` 的「正在思考与处理…」。`transcriptLoading` 仅用于恢复历史记录。此前对话区、连接按钮、模型按钮分别展示加载文字，footer 还重复播报状态。

## 隐藏界面与连接生命周期

问题：侧栏和编辑器 Webview 原先没有保留隐藏上下文，切走后页面销毁、回来重新挂载，让仍存活的连接看起来像在重新初始化。修复前真实侧栏验证中，Core PID 不变但 Webview ID 改变，说明页面和服务的生命周期被混淆。

目标边界：ChatController/AppServerHost 继续拥有连接；ChatSurfaces 只拥有一个可交互页面及其消息、可见性监听。侧栏注册和编辑器创建均启用 VS Code 的 `retainContextWhenHidden`；隐藏不替换 HTML、不重新握手、不调用 connect，保留草稿、选择、展开状态和滚动位置。重新显示时只发布当前 Host 快照、当前审批和编辑器设置，不重放草稿覆盖光标或输入。参考 [VS Code Webview 生命周期与上下文保留](https://code.visualstudio.com/api/extension-guides/webview#retaincontextwhenhidden)；即使保留页面也不把投递成功等同于界面已消费消息，因此显示时重新同步权威快照。

内存范围限于当前页面；侧栏与编辑器互相迁移时仍撤销旧页面监听并清空旧 HTML，真正关闭或退出时释放监听，禁止旧页面消息和可见性事件影响新页面。显式 Webview 重载继续从 Host 恢复当前快照和草稿；整个扩展宿主重启会重新连接。初始化动效只由真实 connecting 状态驱动，不因可见性变化重播。没有新增缓存、定时器、RPC、目录请求或服务重启机制。

## 欢迎区初始化动效

## 打开聊天时初始化

默认 `codem.autoConnect=true`，聊天 Webview 首次就绪时初始化连接；仅激活扩展、不打开聊天时不连接。每次扩展激活最多自动尝试一次，重复 ready、Webview 重载及设置/信任事件不重复初始化；失败后由用户显式重试，不循环重连。用户显式关闭此设置后，首次普通消息仍在 Controller 内完成连接后继续同一次发送。Webview 与 Host 都允许未连接时提交普通消息；请求标识和草稿修订继续由现有 ComposerSubmission / ChatSurfaces 管理，成功回执才消费原草稿，新编辑和失败草稿保留。Controller 只持有一个进行中的发送请求，重复提交立即拒绝；连接失败、选择取消、工作区不可信、宿主退出均不继续发送。新会话或连接代次变化会使尚未发送的请求失效，不持久化自动重试队列。

输入栏菜单均在本地展开，不触发连接。模式、权限和强度可离线选择，附件可通过本地文件对话框添加；模型和空间只展示当前连接提供的目录，没有目录时显示未加载。打开聊天默认提前连接；尚未连接时，首次发送、显式连接和读取历史仍可按需连接；具体行为见 `localComposerMenus.md`。历史和设置异常导致断开后，新的显式发送重新连接并创建新会话，不向状态不明的旧 thread 发送。Webview 重载恢复草稿并复用现有连接；Extension Host 重启后，打开聊天会重新初始化，但不自动发送草稿。

保留公开设置 `autoConnect`，尊重用户显式关闭自动连接的选择；默认值与 Host 读取默认值均为 true，没有临时兼容分支或新缓存。未信任或未打开文件夹时不自动连接，授予信任后重新检查。默认扩展冒烟测试通过专用临时工作区显式关闭自动连接，避免访问真实 Core。

调用链：聊天 ready → connect → 既有认证/空间准备 → 一个 App Server 连接 → 一次模型目录读取 → MCP 与偏好恢复；用户发送时才执行 thread/start → turn/start。连接完成后不再次初始化或拉取模型目录，后续消息仅走原有发送路径；原有授权校验、Connection runtime / MCP / phase 分段耗时日志不变。打开聊天默认一次连接，不创建会话或请求模型回复；重复 ready 不再连接。自动连接行为通过 autoConnect.test.ts 的扩展入口测试验证：未打开聊天、未信任、无工作区、首次就绪、重复/并发事件、Webview 重载、显式重试、关闭与重新启用设置。

本次验证：`pnpm check`（含 183 项 VS Code 测试）、扩展构建、脚本语法及 diff 检查通过。控制器与命令测试覆盖首次发送、无效输入不连接、重复发送、连接失败/取消后重试、授权拒绝、退出后迟到连接回收、新会话失效、模型选择及历史按需连接；原草稿回执测试继续覆盖失败和后续编辑保留。模拟界面验证默认无加载、未连接发送可用、拒绝回执保留草稿。独立生命周期浏览器脚本已更新，未执行；未运行真实 Core 模型请求。现有 VS Code 窗口检查为空闲，但尝试重载时用户接管了窗口，未完成真实宿主验收。

## 提交时立即显示消息

之前消息在 `ensureThread` 完成后才加入列表，因此等待连接期间先显示处理提示，稍后插入用户气泡导致跳动。现在 Controller 在接收有效提交时创建唯一 submissionId 和待发送消息；每个快照在正式消息尚未写入时投影该消息，连接绑定与 thread 创建均不丢失它。正式发送复用相同 ID，Webview 保留同一个 DOM 节点。收到 Host 消息前不抢先隐藏空白欢迎页展示孤立处理提示。

待发送消息只属于当前 Controller 的发送请求，不写入 Core 历史；接受后由正式消息承接，失败/取消后移除预览，原草稿按已有回执协议保留。重试生成新 ID；新会话、迟到连接、退出继续遵守发送请求失效规则。重载 Webview 可以从 Host 快照恢复仍在等待的气泡；退出 Host 不自动重发。不增加连接、目录读取或 RPC。

验证：类型检查、构建、静态检查、186 项扩展测试通过。新测试阻塞连接与 thread/start，逐个检查全部快照中的消息 ID 和数量，并验证失败撤回、重试身份。新增两秒慢连接预览；复用现有服务和单个临时标签页，实测 connecting 时气泡已出现，running 时仍为同一个可访问节点，位置与处理提示一致。`lifecycleViewChecks.mjs` 加入 DOM 节点与坐标连续性断言，语法检查通过，未独立执行。未运行真实 Core 模型或真实 VS Code 发送验收。

## 历史分页首屏闪现

历史组件原先把未初始化的分页区域直接插入页面，首个 Host 快照到达后才隐藏。现在复用 `initialSnapshot()` 和组件自身的 render 规则，在挂载分页区域前确定完整初始状态：无会话时分页、重载及更多会话入口均隐藏。首次打开、重载和宿主未响应都遵守同一规则；有真实分页时按快照显示，分页结束或切换到空会话后隐藏。状态仍归 Host 所有，不缓存显示开关，不新增请求、定时器或异步修正。

项目 AGENTS.md 增加首屏准则：挂载前确定控件初始状态，条件入口不能先显示再等待 Host/RPC 隐藏；验收必须覆盖宿主延迟/未响应和条件成立的正向路径。

验证：扩展类型检查、构建、静态检查、11 项历史控制器测试通过。新增 `waitingForHost` 预览屏蔽状态快照，并在现有浏览器内验证首次打开和重载的分页区域/按钮均 hidden，有分页场景均可见，空会话再次 hidden。生命周期浏览器脚本补充这些断言，语法检查通过，未独立执行；未运行真实 Core 或真实 VS Code 操作。复用预览服务，临时标签页验证后关闭。
