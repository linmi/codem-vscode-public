# 刷新后恢复当前聊天

## 问题与目标边界

2026-09-20：Webview 隐藏保留与 Extension Host 重载是两个生命周期。此前重载会销毁 Controller 内存中的 threadId，连接后 bindSession 又建立空白快照；Core 历史仍存在，但应用没有保存“当前打开哪一个会话”。

现在 `sessionHistory/activeConversation.ts` 独立持有工作区存储中的会话书签与写入队列，仅保存 Core threadId。键由规范化工作目录、认证账号身份（服务地址、租户、用户）和空间键共同散列。账号身份来自现有 SpaceDirectory，不新增凭据存储；身份不完整时明确报告不能恢复/保存，不使用跨账号默认作用域。聊天正文仍只从 Core schema 13 JSONL 读取。

Controller 负责当前会话选择与连接协调；入口注入 workspaceState 适配，历史恢复继续复用 ConversationHistory 的校验、订阅事务、游标及取消边界。不新建消息缓存、不从最近时间猜测当前聊天、不增加另一套恢复协议。

## 交互与保存范围

| 场景 | 行为 |
| --- | --- |
| 首次使用，无书签 | 初始化完成进入空白聊天，不创建 Core thread |
| 已有书签后刷新窗口 | 连接后读取对应书签，校验并恢复同一 Core 会话及最新一页消息；恢复期间保持 connecting，完成后才 ready |
| 手动打开历史聊天 | 保留列表白名单校验，成功投影历史后更新书签；旧会话恢复失败不覆盖原书签 |
| 首次发送、原生会话创建、工具目录、生成功能创建线程 | Core 确认新 ID 后保存书签，不等待下一次用户操作或退出才保存 |
| 新建会话 | 原订阅成功释放后清除书签；下次重载继续空白。离线新建意图由当前 Controller 保留，到下一次已认证连接时清除该作用域书签 |
| 清空会话 | 保存 Core clear 返回的新 ID；归档/删除导致当前线程关闭时清除书签 |
| 空间/账号/工作区切换 | 仅恢复目标作用域书签，不读取其他作用域的选择 |
| 恢复失败或实时事件中止恢复 | 明确提示，保留书签供重试，不创建替代会话；订阅清理状态不确定时断开 |
| 离线输入触发连接且存在书签 | 恢复原聊天，返回未发送回执保留草稿，需要用户再次发送；失败同样不转投空白线程 |
| 重复操作/退出 | 初始化期间禁止重入；旧连接迟到结果不得提交。书签写入顺序化，退出等待已排队写入；连接退休不删除书签 |

初始化期间不允许新建会话打断未完成的恢复。旧测试依赖 bookkeeping 尚未完成就发布 ready 的中间状态，已改为验证 connecting 期间拒绝重复操作，完成后才继续原先的一次发送。

升级说明：旧版本没有会话书签，无法准确反推用户最后打开的会话。升级后首次从历史列表选择一次即可建立书签，不自动选择“最近的”聊天。

## 调用链与准出

自动恢复复用现有手动恢复链：连接与认证 → 读取本地书签 → authorize → thread/read（校验 ID 与 cwd、拒绝归档）→ thread/resume → modes/read → 本地历史读取及既有授权 → 消息投影 → 书签保存入队 → ready；恢复调用等待保存结束。恢复不调用 thread/list、thread/start 或 turn/start，不新增恢复专用进程；认证仍使用已有运行时检查，书签不是授权凭据。上述 RPC 各执行一次，串行依赖来自候选订阅及历史事务；fixture 验证恢复一次、历史读一次、创建与发送零次。

准出标准：重建 Controller 后恢复相同 ID 与消息；成功恢复前没有空白 ready 快照；新建后书签清空；三维作用域互不串用；失败、取消、晚到、保存异常可验证；不自动发送或创建线程。状态模块仅依赖 Node crypto 和窄存储接口，不反向依赖 Controller、Webview 或 VS Code。
