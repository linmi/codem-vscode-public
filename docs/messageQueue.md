# 运行中消息排队

## 问题

主任务运行时，输入栏只能发补充指令（steer）：新文字会并入当前轮次，没有办法先写好“下一件事”等本轮结束再发。

## 行为

- **首次使用**：运行中在普通输入里按发送键或点“加入排队”，消息进入输入框上方的排队列表，草稿在宿主回执受理后清空；补充当前轮次改用 `/steer`。
- **重复操作**：可连续排队，最多 20 条；超出时回执拒绝，草稿保留。
- **编辑与移除**：每条都有“编辑”和“移除”。编辑在原位展开文本框，保存才提交，Esc 或“取消”放弃修改；Ctrl / Cmd + Enter 保存。
- **自动发送**：只有本轮以 `turn/completed` 且结果为完成时，宿主才把队首作为新一轮发送，之后每完成一轮再发下一条。上下文压缩、回退等控制轮次先重载记录再发送。
- **停止与失败**：本轮被停止或失败时队列暂停，任何条目都不会自动发送；之后即使另发一条消息并完成，也不会恢复。用户点“继续发送”才发送队首。
- **发送失败**：Core 未受理的队首放回原位并暂停，给出提示，不自动重试。
- **切换上下文**：新建会话、切换或关闭会话、切换空间、断线和退出登录都会让当前线程变化，队列随之丢弃。
- **重载**：Webview 重载后从宿主快照恢复列表；扩展宿主重启不保留队列。
- **不支持的宿主**：快照没有 `messageQueue`（如 JetBrains 当前版本）时，运行中输入仍按补充指令发送。

## 边界与状态

| 状态 | 所有者 | 保存范围 | 清理时机 |
| --- | --- | --- | --- |
| 排队条目、是否暂停 | `apps/vscode/src/chat/messageQueue.ts` | 当前 Core 线程，仅内存 | 线程变化时（`ChatController.publish` 调用 `follow`） |
| 何时发送队首 | `ChatController`（`turn-completed` 分支与 `resumeQueue`） | — | — |
| 正在编辑的文字 | `packages/ui/src/chat/messageQueue.tsx` | 当前组件 | 保存、取消或条目消失 |

排队发送只带文字：附件、代码选区和已选技能属于输入框里下一条手写消息，不会被较早排队的消息带走。界面只收到条目的不透明 id 与文字；新增动作 `queueMessage`、`editQueuedMessage`、`removeQueuedMessage`、`resumeQueue` 由共享契约与宿主各自校验。没有新增 RPC、子进程或缓存；每条排队消息在发送时恰好调用一次 `turn/start`。

## 验证

- 单元 / 集成：`apps/vscode/tests/messageQueue.test.ts` 覆盖顺序发送、编辑与移除生效、停止和失败后不自动发送、空闲与过期线程拒绝、线程关闭丢弃、Core 拒绝后放回并暂停；`viewActionRouter.test.ts` 覆盖路由；`packages/ui/tests` 覆盖动作校验、快照归一化及首屏与运行中渲染。
- 模拟界面：`apps/vscode/tests/messageQueueChecks.mjs` 在浅色 1440 与深色 380 宽度下实际排队、编辑（含 Esc 放弃）、移除、停止后暂停与继续发送，并检查无横向溢出与控制台错误。
