# 独立账户入口

登录拥有独立生命周期，不依赖工作区、空间或聊天 Core。扩展首次打开聊天时读取一次本地认证状态，重复 ready 复用该展示结果；连接与后续受保护操作仍按原规则重新校验认证，展示缓存没有授权效力。

未知状态首屏不显示聊天或登录按钮，避免已登录用户闪过登录页；未登录显示居中登录页，浏览器授权期间提供取消，失败可重试。已登录显示真实头像，点击进入账户页，展示认证实际返回的姓名、用户 ID、租户 ID 和登录方式。固定 CLI 0.1.208 的 auth status 没有头像字段；Host 在验证认证后从同一 CLI 的 config.json 中只投影 auth.oauth.userInfo.avatar_url。姓名首字/人物图标仅在头像缺失或加载失败时使用。

AccountController 只持有本次扩展生命周期的账户展示状态和当前认证操作，不持久化凭据。扩展重载读取认证器真实状态，Webview 重载复用当前展示状态；重复点击不重复启动登录，取消/退出中止认证子进程，过期响应不能覆盖新状态。账户信息不进入 ChatSnapshot、会话历史或 Webview 持久草稿。Host 只向界面发送白名单个人信息，原始认证输出、router credential、server URL 不下发。

登录链：状态读取（auth/status）→ 用户明确点击登录 → 读取当前认证 → 如需登录则启动 auth/login 并打开 HTTPS 授权页 → 认证库核实成功状态。此链不读取模型/空间、不启动 Core。聊天连接继续独立校验认证，并把新鲜状态投影给账户入口；账户页刷新也重新读取。认证被 Core 标记失效时清除账户展示，让用户重新登录。

本轮不新增账号切换、注销或头像上传能力；只展示认证服务可提供的个人信息。

账户页首次打开与主动刷新重新读取信息；重复刷新复用同一请求。刷新期间禁用刷新按钮，失败保留已有账户与聊天，只显示可重试提示。返回按钮或 Escape 关闭账户页并恢复头像入口焦点；聊天 DOM 不卸载，草稿和消息滚动位置保持。Webview 重载、侧栏/标签页切换后个人页默认关闭；工作区与会话切换不改变全局账户身份。

## 操作次数与验证

首次打开读取 1 次 `auth/status`；同次扩展生命周期的 Webview 重载不新增认证子进程。用户主动登录先读取 1 次状态；仍未登录时启动 1 次 `auth/login`，成功后认证库再读取 1 次 `auth/status` 核实结果。点击头像或主动刷新各读取 1 次状态，并合并未完成的重复请求。上述账户流程的 Core / 空间 / 模型请求均为 0；之后真正连接聊天时独立校验。日志仅记录 `Account status/login: Nms` 阶段耗时，不记录身份、凭据或授权 URL。

取消覆盖浏览器授权等待、登录子进程和成功后的最终状态校验；认证库测试使用忽略 SIGTERM 的 fixture，验证取消后进程被回收。已成功完成的服务端授权不会因取消本地等待而注销账户，下次登录仍读取真实状态。

验证：`pnpm check`（静态检查、类型检查、单元/集成）和正式/原生实验构建通过。账户回归覆盖初始化、重复操作、取消/重试、失效、脱敏投影、刷新失败保留、退出清理及登录不依赖工作区/Core。模拟界面复用 4318 服务和单个临时标签页，检查浅色/深色、1280×720、380×640、320×480、真实按钮登录/取消/重试、个人信息、Escape/返回焦点、草稿保留与页面高度；浏览器控制台无错误。`accountPreviewChecks.mjs` 接入既有富界面检查入口；本轮通过浏览器工具执行相同行为，未单独执行该 CLI 脚本。

真实 Core：未请求模型，也未进行真实登录。真实 VS Code：已有开发宿主正在被用户使用，自动化交互被用户操作打断；本轮未重载窗口，未把模拟验证视为真实宿主验收。

## 头像资料边界（2026-09-20）

本轮问题：CLI 状态输出只含身份摘要，但本地 OAuth userInfo 已包含 avatar_url，之前只看状态输出而遗漏了这份展示资料。当前机器已只读核实字段存在，真实图片 HEAD 返回 200 / image/jpeg。方案参考桌面端 `/Users/linmi/Developer/codem/src/main/codem/authentication.ts` 的 readDisplayUser（提交 321c540c2910655e90a2ff3d75ff40e22fa1f38f），未复制其 token provider、兼容字段或状态管理。Webview Avatar 基础组件采用 shadcn/ui 官方 new-york-v4 Avatar 的 Root/Image/Fallback，保留 MIT 许可，来源 https://ui.shadcn.com/r/styles/new-york-v4/avatar.json；复用现有 radix-ui，不新增依赖。

Host 的 accountAvatar.ts 负责限量只读展示资料，白名单字段为 avatar_url；认证仍完全通过 CLI。路径遵循已核实的 CLI 0.1.208 CONFIG_PATH 规则（CODEM_HOME，BOE 子目录），不把 CODEM_STATE_HOME 当作认证目录。仅当已验证状态的 serverUrl、tenantId、userId 与 OAuth 资料一致时下发头像；不写配置，不返回 token、整份 userInfo、邮箱或本地路径。缺失头像为 none，损坏、超限、身份不匹配或非法地址为 unavailable；后者显示可刷新提示，不改变登录状态。

首次读取、登录成功、主动刷新：在现有认证成功后追加一次最多 1 MiB 的本地读取，不新增认证进程、Core 或个人信息网络 API。头像 URL 仅允许 HTTPS 的 feishucdn.com / larksuitecdn.com 及其子域，拒绝凭据、其他域和额外端口；同一允许列表生成 Webview img-src。浏览器只请求头像图片，使用 no-referrer；尺寸固定 24/56px，缺失或图片失败由 shadcn AvatarFallback 显示首字，不出现破图或挤压布局。

AccountController 独占展示头像的生命周期，仅内存保存；Webview 重载复用账户快照，扩展重载重新读认证及资料。运行时对同一身份的认证观测保留头像，更换身份或认证失效立即移除，旧头像读取不能覆盖新身份。打开个人页/主动刷新重新读取资料，并允许图片重新加载；网络失败不影响聊天，返回、取消和切换上下文沿用账户页既有语义。没有新增凭据缓存或自动刷新循环。

本轮验证：`pnpm check` 与正式/原生实验构建通过；新增回归覆盖身份匹配、URL 白名单、缺失/损坏/超限文件、取消和旧身份响应失效。模拟界面复用 4318 服务，验证浅色与 380×640 深色、图片成功、加载失败首字兜底、固定尺寸及刷新重试；失败场景的图片 404 为预期结果。`accountPreviewChecks.mjs` 已补充对应检查，本轮通过浏览器工具执行同等操作，未单独运行该 CLI 脚本。

真实 VS Code：复用并重载已有开发宿主，已登录账户的入口和个人页均显示真实头像，账户刷新完成，Escape 返回聊天并恢复入口焦点，原会话仍保留。该结果更新前一轮未完成的宿主验证。真实 Core 随原会话恢复连接，本轮未发送模型消息，也未执行新的浏览器登录；不将现有登录态的验证视为新登录流程验收。验证临时标签已关闭，视口已恢复。
