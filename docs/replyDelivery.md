# 正文回复与结构化收尾

2026-09-20：用户确认关闭强制收尾，恢复普通正文回复。

## 问题与证据

截图对应的 Core 0.8.37 schema 13 会话中，两次用户消息均先生成完整 `assistant_text`，随后由 Core 注入 synthetic 用户消息，要求再调用 `final_answer`。每次用户消息实际发起两次模型请求。第二次消息的原始正文包含完整工具列表，请求记录中有 30 个工具；工具注册未丢失。

Host 启动时无条件添加 `--final-answer-tool`，触发强制收尾。ChatController 将 `final_answer.summary` 写入上一条 assistant 消息，进一步将原正文覆盖为“已说明……”的总结。历史读取器原本就将正文与结构化交付分开保留，实时投影与历史不一致。

## 目标行为与状态所有权

- 新连接启动 Core 不传 `--final-answer-tool`。Core 0.8.37 与本次工作区同步升级后的 0.8.44 随包 `--help` 均说明：默认不注册该工具。模型通过普通正文回答，客户端仍只以 `turn/completed` 判断实时终态。
- 首次发送、同一会话继续发送、恢复历史后发送均使用相同连接配置。停止仍等待 Core 终态；失败保留已收到正文，后续重试遵循现有发送归属规则，不追加客户端总结。
- 每条正文由 Core item ID 标识。旧连接或已持久化历史中的结构化交付仍保留独立身份及产物卡片，不替换已输出正文；重复生命周期通知更新同一交付，晚到正文只更新自己的消息。
- Host 持有当前会话消息；Webview 只渲染快照。重载从 Core schema 13 恢复；新会话/切换上下文沿用现有消息替换和资源句柄失效规则，不修改既有 JSONL。
- 不新增请求、缓存或持久化状态。移除引发二次收尾的启动参数，不改变认证、审批或工具加载。后续发现的 Core 完成度自检路径按下节单独关闭。

## 用户已确认的影响

新连接不再提供 `final_answer` 的结构化文件、图片、链接、图表产物卡片；普通正文、Markdown、常规工具执行与文件差异展示继续按原协议工作。已有历史卡片保留读取与打开能力，因此相应解析器和历史测试仍然需要保留，删除条件是将来明确迁移旧持久历史格式。

已有 Core 子进程的启动参数不会热更新。需加载新扩展构建并重新建立 Core 连接后生效；仅在旧连接里点击新建会话不会改变进程参数。

## 正文与执行记录的折叠边界

2026-09-21 按用户进一步反馈修正：同一轮的工具、思考与中途进度说明共用一个“已处理”折叠区。进度说明依据位置判定：同一用户消息范围、同一 turnId 内，后面仍有执行记录的 assistant 文字归入处理过程；最后一次执行之后的答复和补充正文保留在外。带产物的交付保持独立。不同 turnId 和新用户消息隔离判定，不按“Wiki”等关键词猜测，不删除或改写内容。尚无后续执行证据的流式正文先保持可见，确认后移入原处理组，实时与历史回读使用同一规则。

组内保留思考、说明和工具的原顺序。分组以首个归入处理过程的消息 ID 复用节点及用户展开状态；已存在的组不会因追加进度或工具而更换身份。工作分组类型只允许执行记录或 assistant 说明，不允许用户消息。最终答复保留复制操作；折叠区内的说明使用已有样式，收起时不留下独立消息、复制按钮和消息间距。轮次运行或失败默认展开，完成默认收起；手动收起不被后续快照覆盖。计时继续来自 Core，并在每轮唯一处理组显示一次。

取消、失败和切换会话沿用原有生命周期；清空或移除记录时回收对应折叠组及定时器。不增加请求、缓存或持久化字段。不需要调用模型来决定哪些文字应当隐藏，也不按正文内容做特殊匹配。

## 历史正文恢复的顺序

截图会话 `25a4f42ed5974fa6b282f2b7f8766dd8` 的 durable 顺序为 `turn_response → thinking → assistant_text`。旧读取器在处理审计用的 `turn_response` 时先创建正文，后续正式正文只原位更新，导致历史投影变成“正文 → 思考”。折叠分组保留了这个错误顺序。

现在 `turn_response` 中的正文仅作为当前解析轮次的恢复候选暂存，不提前占据消息位置。正式 `assistant_text` 决定正文内容与位置；正式思考与工具记录仍按原始顺序进入时间线，不在界面按角色强行重排。若停止、错误、工具执行或 EOF 前没有正式正文，则保留从审计记录恢复缺失正文的能力。EOF 预览不消耗候选状态，后续继续读取或恢复解析快照不会重复正文。

状态只属于单个读取器的当前轮次，在正式正文或恢复边界清理；内部快照字段及调用方已原子更新。当前对外包入口只读取 Core JSONL，没有持久化这些解析器快照的生产调用方；原始 JSONL、Core 协议和会话文件均不改写。首次打开、重新打开、切换会话和历史分页使用同一解析器；取消与错误仍保留已有内容。

验证：历史包回归覆盖正式顺序、审计/正式正文不同、EOF、取消、失败、多轮工具交错、缺失正文恢复、重复候选拒绝和解析快照恢复；`pnpm check` 与扩展构建通过。真实 Core 的 `test:live --reply-delivery` 同时验证实时与历史末段是正文。原截图会话回读与浏览器 DOM 均确认为 `user → work → assistant`，折叠区位于正文上方，正文未进入折叠区。浏览器使用真实历史投影（思考内容以占位文本代替）；未执行真实 VS Code 点击验收。

## 同轮处理分组不再被中途说明拆开
