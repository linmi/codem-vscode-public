# 正文回复与结构化收尾

2026-09-20：用户确认关闭强制收尾，恢复普通正文回复。

## 问题与证据

截图对应的 Core 0.8.37 schema 13 会话中，两次用户消息均先生成完整 `assistant_text`，随后由 Core 注入 synthetic 用户消息，要求再调用 `final_answer`。每次用户消息实际发起两次模型请求。第二次消息的原始正文包含完整工具列表，请求记录中有 30 个工具；工具注册未丢失。

Host 启动时无条件添加 `--final-answer-tool`，触发强制收尾。ChatController 将 `final_answer.summary` 写入上一条 assistant 消息，进一步将原正文覆盖为“已说明……”的总结。历史读取器原本就将正文与结构化交付分开保留，实时投影与历史不一致。

## 目标行为与状态所有权

- 新连接启动 Core 不传 `--final-answer-tool`。Core 0.8.37 与本次工作区同步升级后的 0.8.44 随包 `--help` 均说明：默认不注册该工具。模型通过普通正文回答，客户端仍只以 `turn/completed` 判断实时终态。
- 首次发送、同一会话继续发送、恢复历史后发送均使用相同连接配置。停止仍等待 Core 终态；失败保留已收到正文，后续重试遵循现有发送归属规则，不追加客户端总结。
- 每条正文由 Core item ID 标识。旧连接或已持久化历史中的结构化交付仍保留独立身份及产物卡片，不替换已输出正文；重复生命周期通知更新同一交付，晚到正文只更新自己的消息。
- Host 持有当前会话消息；Webview 只渲染快照。重载从 Core schema 13 恢复；新会话/切换上下文沿用现有消息替换和资源句柄失效规则，不修改既有 JSONL。
- 不新增请求、缓存或持久化状态。移除引发二次收尾的启动参数，不改变认证、审批或工具加载。后续发现的 Core 完成度自检路径按下节单独关闭。

## 用户已确认的影响

新连接不再提供 `final_answer` 的结构化文件、图片、链接、图表产物卡片；普通正文、Markdown、常规工具执行与文件差异展示继续按原协议工作。已有历史卡片保留读取与打开能力，因此相应解析器和历史测试仍然需要保留，删除条件是将来明确迁移旧持久历史格式。

已有 Core 子进程的启动参数不会热更新。需加载新扩展构建并重新建立 Core 连接后生效；仅在旧连接里点击新建会话不会改变进程参数。

## 正文与执行记录的折叠边界

用户明确要求只折叠 tools 等记录。时间线现在仅将连续的 `tool` / `reasoning` 记录归入折叠区；`user` / `assistant` 正文始终独立、按原顺序显示。正文和不同 turnId 都切断执行分组，不将后续工具移动到前面的文字之前。`TimelineGroup` 的 work 分支只接受 `ActivityMessage`，从类型边界排除正文。

首次渲染、流式追加、重复快照和历史回读共用同一分组函数。新工具或补充回复出现时，已有正文保持可见、复制按钮保留；旧历史中的总览和核对说明也都会显示在折叠区外，不修改持久记录。每组沿用首条执行记录 ID 保留用户展开状态；运行或失败记录默认展开，完成默认收起。轮次仍活跃时只让最新执行组跟随当前阶段，已经完成的较早执行组不因后续工具再次运行而重新展开。计时仍来源于 Core 轮次，仅在该轮最后一个执行组显示一次，不推算各分组独立耗时。

取消、失败和切换会话沿用原有生命周期；清空或移除记录时回收对应折叠组及定时器。不增加请求、缓存或持久化字段。不需要调用模型来决定哪些文字应当隐藏，也不按正文内容做特殊匹配。
