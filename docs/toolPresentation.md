# 工具调用展示

## 边界与依据

本轮问题是工具调用展示覆盖不足：内置工具经常直接显示英文名字，参数范围丢失，MCP 名称重复，模拟预览还手动提供真实调用没有投影的字段。

依据本机 Core 0.8.44 的 `discovery list builtin`（31 项）、对应二进制内嵌的工具输入说明、App Server item 类型及本项目 schema 13 历史记录实现。条件工具 `describe_image`、`exit_plan_mode` 和 `contextCompaction → compact` 单独覆盖；`final_answer` 继续走最终回复投影。

- Host 的 `src/chat/toolDetails.ts` 是实时调用与历史记录共用的白名单投影；任务清单由 `taskDetails.ts` 投影为专用 DTO。
- Webview 的 `webview/transcript/toolPresentation.ts` 只消费工具身份、状态和显示字段，输出不被猜测性解析成参数或摘要。
- 折叠行只列关键对象，详细选项在现有展开区显示。保留原有图标、字号、间距和“已处理”分组。
- 不引入缓存、RPC 或子进程；消息状态仍归会话控制器所有，工具组件只持有本节点的展开状态。首次运行展示加载状态；重复快照和终态更新保留用户展开选择；失败仍按已有规则自动展开。新会话和上下文切换释放旧节点，历史未终结调用显示“未完成”，不重启为运行中。

## 覆盖内容

| 类别 | 关键内容 |
| --- | --- |
| 文件、目录、搜索 | glob 模式、搜索范围、文件过滤、输出模式、上下文、分页、每个文件的读取行范围、目录深度与隐藏文件 |
| 修改与验证 | 文件、批量修改数、替换行段或插入位置、验证命令、Shell 超时与后台选项 |
| 后台进程 | 当前工作区范围、PID、日志字节游标、过滤条件 |
| 子任务 | 名称、代理、oneshot/supervised 模式、执行权限、任务和问题 ID、回复内容；派发完成不等于任务完成 |
| 任务与用户交互 | 创建/更新任务的专用内容；问题、单选/多选选项、计划原因及内容 |
| 安装与工作树 | 安装来源、范围、服务器、传输方式、生效条件；工作树名称、保留/移除及丢弃更改选项 |
| 图片、等待、上下文 | 图片引用或安全文件名、识别关注点、秒数、替换和保留的记录数 |
| MCP | 从协议命名中分离服务器和工具名；折叠标题只出现一次工具身份，不转发任意 MCP 参数 |

运行、完成、失败、拒绝、中断和未完成均有明确文案。未知工具保留名称，并使用通用调用状态；不冒充已知工具。路径沿用工作区相对路径/外部文件名规则，URL 去除认证信息及敏感查询参数；不向预览发送原始工具参数、环境变量、MCP 启动参数或文件全文。

## 预览与回归

`tests/previewToolSamples.ts` 保存 Core 输入样例。`pnpm build:vscode` 运行真实 Host 投影，生成 `tests/fixtures/previewTools.ts`，浏览器只导入生成的显示 DTO。生成文件提交到仓库以支持独立类型检查与测试；测试逐项比较真实投影和生成文件，手改详情或生成结果过期会失败。修改投影或样例后重新执行构建（包括 watch 会话）。

- `toolDetails`：六类工具的原有预览入口，移除伪造的退出码、网页标题等输入详情。
- `allToolDetails`：35 个样例，含全部 31 个发现的内置工具、3 个条件事件和 1 个 MCP 调用，轮换六种状态。
- `toolDetails.test.ts`：覆盖工具清单、输入边界、秘密字段隔离、MCP 去重、实时 item/历史投影一致性及生成文件一致性。
- `toolCoverageChecks.mjs`：复用预览浏览器，验证详情、主题、窄屏、折叠、失败/重试、场景切换和重载。

不再保留手写的六类工具详情数据源；测试里对旧 `read_files.paths` 和双路径输入的引用是预期的负向回归。
